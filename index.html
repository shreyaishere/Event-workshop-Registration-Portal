Browser Storage Architecture: Cookies vs Web Storage

An in-depth conceptual comparison satisfying MCA-1A Web Technology syllabus requirements on client-side state persistence.

Network & Sessions

HTTP Cookies

  • Capacity: ~4 KB per domain
  • Lifetime: Configurable via Expires or Max-Age
  • HTTP Traffic: Sent automatically with every matching HTTP request header
  • Security: Protected via HttpOnly and Secure flags against XSS/MITM
  • Best For: Session IDs, server authentication tokens, CSRF protection
roster usage: Not used for client state to avoid unnecessary HTTP payload overhead.
Persistent Client Storage

localStorage

  • Capacity: ~5 MB to 10 MB per origin
  • Lifetime: Persists indefinitely across browser restarts until cleared
  • HTTP Traffic: Purely client-side; never sent over HTTP request headers
  • Security: Accessible via JavaScript; vulnerable if untrusted scripts run
  • Best For: User theme preferences, offline caches, non-sensitive history
roster usage: Persists eventPortalTheme and non-sensitive confirmed registration log.
Tab-Scoped Transient Storage

sessionStorage

  • Capacity: ~5 MB per origin per browser tab
  • Lifetime: Scoped strictly to the lifetime of the active browser tab
  • HTTP Traffic: Purely client-side; never sent over HTTP request headers
  • Security: Isolated per tab; cleared automatically when tab is closed
  • Best For: Multi-step form wizards, registration drafts, transient view state
roster usage: Auto-saves registrationDraft (strictly excluding passwords).

Defensive Application Security

Client-Side XSS Protection & Sanitization

Demonstrating why roster relies strictly on safe DOM properties like textContent rather than executable sinks like innerHTML.

When untrusted user input (such as names, comments, or draft values) is inserted into the DOM via innerHTML, the browser parser executes any embedded <script> or <img onerror> payloads. By using document.createElement() and element.textContent, user input is strictly treated as text characters, preventing DOM-based Cross-Site Scripting (XSS).
